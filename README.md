#Explore with Me
Приложение-афиша, позволяющее пользователям делиться информацией об интересных событиях и находить компанию для участия в них.

#Описание
Explore With Me — платформа для мероприятий. Тут можно создавать события, присоединяться к ним, формировать подборки интересного и делиться впечатлениями в комментариях.
---
### Стек:
Java: 21,Java Core,Spring Boot 3.3.2,
Microservice: Spring Cloud(Gateway, Config Server, Eureka, OpenFeign)
Database: PostgreSQL 16
ORM: Hibernate,Spring Data JPA
project: Maven


---
Система разделена на несколько микросервисы, общий используют реляционную бд, таблица разделена по схеме микросервиса, в файле schema.sql.
--

### Конфигурация
Все конфиги сервиса находятся в своем локальном src/main/resource/ файле, называется application.yaml и он импортирует Конфиг Сервер и Еврику, так же имя приложение.


---
Внутренный API
--
Микросервисы должен друг друга общается через с помощью FeignClient,из модули Interaction-api, Для отказоустойчивости мы используем Circuit Breaker


---
1. Event-Service
   Управление событиями:
    - Создание, редактирование и удаление событий
    - Категории событий
    - Подборки (compilations)
    - Управление запросами на участие

#### Роль Админ
- `GET /admin/events` — получить список событий с фильтрацией по пользователям, статусу, категориям и диапазону дат
- `PATCH /admin/events/{eventId}` — обновление события администратором
- `POST /admin/categories` — создание категории
- `PATCH /admin/categories/{catId}` — редактирование категории
- `DELETE /admin/categories/{catId}` — удаление категории

#### Публичный
- `GET /events` — список всех событий с фильтрацией по тексту, категориям, оплате, диапазону дат, доступности
- `GET /events/{id}` — получение детальной информации о событии
- `GET /categories` — список категорий
- `GET /categories/{catId}` — получение категории по id

#### Приватный (для пользователей)
- `GET /users/{userId}/events` — список событий пользователя
- `POST /users/{userId}/events` — создание нового события пользователем
- `GET /users/{userId}/events/{eventId}` — детальная информация о событии пользователя
- `PATCH /users/{userId}/events/{eventId}` — обновление события пользователем
- `GET /users/{userId}/events/{eventId}/requests` — список запросов на участие в событии
- `PATCH /users/{userId}/events/{eventId}/requests` — обновление статусов запросов

---
2. User-Service
   Управление пользователями:
    - Создание и удаление пользователей
    - Получение информации о пользователях
    - Поддержка пагинации при получении списка

#### Роль Админ
- `POST /admin/users` — создание пользователя
- `GET /admin/users/{id}` — получение пользователя по id
- `GET /admin/users` — получение списка пользователей с фильтрацией по id и пагинацией
- `DELETE /admin/users/{id}` — удаление пользователя

---
3. Request-Service
   Управление запросами пользователей на участие в событиях:
    - Просмотр всех запросов пользователя
    - Создание нового запроса на участие в событии
    - Отмена запроса пользователем

#### Приватный (для пользователей)
- `GET /users/{userId}/requests` — получить все запросы пользователя
- `POST /users/{userId}/requests?eventId=<id>` — создать новый запрос на участие в событии
- `PATCH /users/{userId}/requests/{requestId}/cancel` — отмена запроса пользователем

---
4. Comment-Service
   Управление комментариями пользователей к событиям:
    - Создание, редактирование и удаление комментариев
    - Получение комментариев по пользователю, событию или по id

#### Приватный (для пользователей)

- `POST /users/{userId}/comments` — создать комментарий к событию
- `PATCH /users/{userId}/comments/{commentId}` — обновление комментария пользователем
- `DELETE /users/{userId}/comments/{commentId}` — удаление комментария пользователем
- `GET /users/{userId}/comments` — получить все комментарии пользователя с пагинацией
- `GET /users/{userId}/comments/events/{eventId}` — получить комментарии пользователя по конкретному событию с пагинацией

#### Публичный

- `GET /events/{eventId}/comments` — получить все комментарии к событию
- `GET /comments/{commentId}` — получить комментарий по id

---

### Зависимость

event-service поздоровается с user-service и request-service,
request-service поздоровается с event-service для получение инфу о событиях,
comment-service поздоровается с user-service и event-service,
